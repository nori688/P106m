# system-power

Раскладывает **штатный режим работы GNOME** по всей системе: процессор,
память и шина, графика, **обои и интерфейс рабочего стола**.

Переключатель — тот самый «Режим работы» в GNOME (Настройки → Питание, он же
в быстром меню справа сверху). Отдельного интерфейса у system-power нет:
щёлкнул в GNOME — перестроилась вся система.

Три режима × два состояния питания:

| | Performance | Balanced | Power («картошка») |
|---|---|---|---|
| **Сеть** | всё на максимум | рабочее | экономия, но не овощ |
| **Батарея** | быстро, но с оглядкой | рабочее-экономное | максимум экономии |

Источник питания определяется автоматически — вынимаешь зарядку, и в том же
режиме подставляются «батарейные» числа. Ничего переключать не надо.

## Откуда берётся режим

За штатные три режима отвечает **power-profiles-daemon** (`powerprofilesctl`,
D-Bus `org.freedesktop.UPower.PowerProfiles`). Соответствие простое:

| GNOME | system-power |
|---|---|
| `performance` | performance |
| `balanced` | balanced |
| `power-saver` | **power** (картошка) |

Демон опрашивает PPD раз в 5 секунд и на изменение раскладывает профиль.
Поэтому `system-power set performance` не только применяет профиль, но и
**переключает сам GNOME** — чтобы меню и система не расходились.

Если PPD в системе нет, режим хранится в `/etc/system-power/mode` — как раньше.

## Что меняется

**Настраивает только картошка** — режим энергосбережения в GNOME. Режимы
производительности и баланса ничего не крутят: они возвращают систему
к снимку, потому что «настраивать производительность» числами ниже заводских
смысла нет.

Живые обои — отдельное правило, оно работает во всех режимах (см. ниже).

### Процессор и мощность

| Ключ | Что делает |
|---|---|
| `CPU_EPP` | `energy_performance_preference`: performance → power |
| `CPU_TURBO` | отключение турбо (`intel_pstate/no_turbo`) |
| `CPU_MAX_MHZ` | потолок частоты (0.8–3.4 ГГц) |
| `CPUIDLE` | cpuidle-губернатор: `menu` / `teo` |
| `RAPL_LONG_UW` / `RAPL_SHORT_UW` | лимиты мощности пакета (долгий/краткий) |
| `USB_AUTOSUSPEND` | агрессивность засыпания USB |

### Графика

| Ключ | Что делает |
|---|---|
| `IGPU_MAX_MHZ` / `IGPU_MIN_MHZ` | потолок и пол частоты встроенной графики |
| `WALLPAPER_FPS` | лимит кадров обоев: 20 от сети, 10 от батареи |
| `WALLPAPER_GPU` | в картошке обои переезжают на встроенную графику (`intel`) |

### Интерфейс

| Ключ | Что делает |
|---|---|
| `GTK_THEME` / `ICON_THEME` | `plain` → **Adwaita-dark** |
| `COLOR_SCHEME` | `plain` → `prefer-dark` (светлая режет глаза) |
| `FONT_AA` / `FONT_HINTING` | `grayscale` / `none` — рисуется дешевле |
| `DOCK` | `plain` → непрозрачный, без сжатия |
| `GNOME_ANIM` | анимации оболочки выключаются |
| `EXT_DISABLE` | гасятся иконки рабочего стола и blur |
| `EXTRAS` | `localsearch` (индексатор) и `evolution-*` — стоп + mask |

Фон рабочего стола картошка не трогает: когда движок выключен, виден твой
обычный фон. Губернатор CPU тоже не трогается — он обязан оставаться
`powersave` (см. грабли ниже).

### Живые обои по режимам

Живые обои и «примитив» в интерфейсе разведены по питанию:

| | Сеть | Батарея |
|---|---|---|
| performance | живые обои, обычный вид | **живые обои**, обычный вид |
| balanced | живые обои, обычный вид | движок выключен, твои обычные обои |
| power | живые обои, но тема тёмная и примитив | движок выключен, тёмный Adwaita, анимации и эффекты выкл |

То есть **в сети обои живые во всех трёх режимах**. На батарее движок
выключается полностью, и на рабочем столе остаётся твой обычный фон
(`BACKGROUND=baseline`) — экономия максимальная, а не «анимация помедленнее».

Включить живые обои на батарее можно только одним способом — переключиться
в режим производительности.

Тема «картошки» — **Adwaita-dark** с `prefer-dark`: светлый Adwaita в темноте
бьёт по глазам.

## Как это не ломает твои настройки

Режим «картошка» ставит Adwaita, сплошной фон и гасит расширения. Чтобы это
не осталось навсегда, есть **снимок**:

```bash
sudo system-power snapshot     # запомнить текущий вид (делается автоматически при первом применении)
system-power baseline          # посмотреть, что запомнено
```

В таблице профилей `baseline` означает «взять из снимка», `plain` — «сделать
примитив». При возврате в performance/balanced всё восстанавливается **ровно
как было у тебя**, включая список включённых расширений.

Если поменял тему/фон сам — обнови снимок: `sudo system-power snapshot`.

## Использование

Обычно ничего запускать не надо — режим переключается в GNOME. Но CLI есть:

```bash
system-power                 # статус: режим, питание, что применено
system-power set power       # картошка (и переключит режим в GNOME)
system-power set balanced    # баланс
system-power set performance # максимум
system-power set auto        # не нужно: питание учитывается само
system-power show            # все числа по режимам
system-power show power      # числа конкретного режима
system-power apply           # применить заново
system-power snapshot        # переснять вид интерфейса
system-power log 30          # журнал
system-power reset           # вернуть balanced
```

Числа правятся в `/usr/local/lib/system-power/lib/profiles.conf`, после правки —
`system-power apply`. Колонок должно быть ровно шесть.

## Установка

```bash
sudo ./install.sh                 # файлы + служба автопереключения
sudo ./install.sh --no-daemon     # только CLI
sudo ./install.sh --with-sudo     # + разрешение вызывать без пароля (для кнопки в панели)
sudo ./install.sh --uninstall
```

Без установки, прямо из репозитория:

```bash
sudo ./bin/system-power set power
```

## Чего это железо НЕ умеет

Честный список — проверено на этой машине, не догадки:

- **Частоту экрана понизить нельзя.** У панели eDP-1 только режимы ~59.93 Гц,
  ни 48, ни 40 в списке нет. Поэтому «30 fps» для всей системы не сделать —
  вместо этого гасятся обои, анимации и лишние эффекты, что и даёт основную
  экономию. VRR тоже недоступен (в `experimental-features` его нет).
- **PCIe ASPM в рантайме не меняется.** Запись в
  `/sys/module/pcie_aspm/parameters/policy` возвращает `I/O error`. На этом
  ядре политику можно задать только параметром загрузки `pcie_aspm.policy=...`,
  то есть одним значением на всё время работы. Скрипт пробует один раз за
  загрузку и дальше молчит (чтобы не сыпать ошибками в журнал).
- **У дискретной NVIDIA нельзя менять ни частоты, ни лимит мощности.**
  `nvidia-smi -lgc` отвечает «locked GPU clocks is not supported», `power.limit`
  = N/A: майнинговая карта не отдаёт эти параметры. Единственный способ
  экономить на ней — не использовать (это и делает `WALLPAPER_GPU intel`).
- **Вендорских профилей нет** — `platform_profile` отсутствует.
- **Порога заряда батареи и управления вентиляторами нет.**

## Как устроено

```
bin/system-power       CLI
daemon/system-powerd   демон: опрос питания и режима GNOME раз в 5 с
lib/common.sh          общее: пути, sp_write, sp_as_user, power-profiles-daemon
lib/profiles.conf      таблица картошки «ключ → сеть / батарея»
lib/snapshot.sh        снимок системы (интерфейс + железо) и возврат к нему
lib/apply.sh           картошка, правило живых обоев, sp_apply
```

Демон опрашивает `/sys/class/power_supply/AC*/online` раз в 5 секунд, а не
подписывается на udev: чтение одного файла стоит ноль, а события о смене
питания приходят не всегда.

`sp_as_user` нужен потому, что демон работает от root, а настройки интерфейса —
пользовательские. Функция находит активную сессию через `loginctl` и выполняет
команду с её `DBUS_SESSION_BUS_ADDRESS`.

## Грабли, которые уже пройдены

1. **Губернатор CPU обязан оставаться `powersave`.** Самая дорогая находка.
   Профиль производительности сначала ставил `scaling_governor=performance` —
   и после этого **режим в GNOME переставал переключаться вообще**. Ошибка
   пряталась в D-Bus:

   ```
   Failed to activate CPU driver 'intel_pstate': Error writing
   '.../policy2/energy_performance_preference': Устройство или ресурс занято
   ```

   Причина: с intel_pstate файл `energy_performance_preference` доступен на
   запись **только при губернаторе `powersave`**. С `performance` любая запись
   туда даёт `EBUSY`, и power-profiles-daemon не может применить свой профиль.
   Симптом при этом выглядит обманчиво: `powerprofilesctl set` возвращает
   ошибку, а `system-power set` пишет «power-profiles-daemon недоступен».
   Решение — губернатор всегда `powersave`, а быстрота задаётся через EPP.

2. **`nohup`/`setsid` не умеют запускать shell-функции.** Перезапуск обоев был
   написан как `nohup sp_as_user ... &` — молча не работал: обои не возвращались
   после картошки. Теперь команда собирается вручную и отвязывается через `setsid`.
3. **В доке `transparency-mode` — enum из `DEFAULT/FIXED/DYNAMIC`.**
   Значения `SOLID` не существует, хотя оно встречается в других форках
   dash-to-dock. Непрозрачный док = `FIXED` + `background-opacity 1.0`.
4. **Выключение расширений на Wayland работает в рантайме**, а вот перезагрузка
   кода — нет. Для `EXT_DISABLE` этого достаточно.
5. **`mask` для пользовательских юнитов** держится до `unmask`. Если
   `EXTRAS=0` применился, а затем машина выключилась в этом режиме — при
   следующем запуске профиль применится заново и всё вернёт.
6. **`need_root` должен получать полную команду.** Внутри `cmd_set` стояло
   `need_root "$@"`, а `"$@"` там — только название режима. Повторный запуск
   через `sudo` получал `system-power balanced` без слова `set` и не понимал,
   чего от него хотят. Теперь передаётся `need_root set "$m"`.

## Дальше

- **Кнопка в панели — уже есть, и писать её не надо.** Режим переключается
  штатным «Режимом работы» в GNOME (быстрое меню справа сверху). system-power
  слушает PPD, так что иконка, меню и система всегда согласованы.
- **«Жарить в выбранном приложении»** — в режиме картошки список приложений,
  при запуске которых ограничения снимаются на время их работы. Механизм уже
  готов в самом PPD: `powerprofilesctl launch -p performance <команда>` держит
  профиль через `HoldProfile`/`ReleaseProfile`, пока команда не завершится.
  Останется следить за появлением процесса и не мешать PPD это делать.
